### 这一版修了什么（相对 0.8.0）

0.8.0 的补丁，修正用户反馈的三个问题，以及排查时发现的 MKV 导出检查漏洞，没有新功能。工程文件、设置、识别结果的格式都没有变。0.8.0 的全部改动见 [0.8.0 发布说明](https://github.com/NOTBAD314/2ByteASR/releases/tag/v0.8.0)。

- **工作台预览时画面和字幕像倍速，声音却是原速**（到后面才重新对上）。工作台的声音由兔白自己输出，画面由播放器按显示器刷新率排帧；显示器的刷新率被系统报错时（例如报成实际的一半），画面就按错误的节奏加快，字幕跟着画面走，声音不变。现在画面按系统时钟播放，不再受刷新率影响；1×、2×、跳转后都与声音同步。
- **双人对话翻译后压制成片，少了一个人的译文。** 其中一人用了高级样式（例如渐变字幕），或者片段在时间轴上裁切过时，那个人的译文进不了成片，导出过程右侧的预览也看不到。现在普通与高级样式、静态与动效、裁切过的片段都保留两人的译文。
- **首页完成页导出的 SRT / TXT 跟随「原文 / 译文 / 双语」显示模式**，以前一律只有原文；分说话人导出同样保留译文。工作台「导出字幕（Ctrl+E）」的原文 / 译文 / 双语选项不变。
- **选了日语（字幕时间轴用 Qwen3 对齐 / 日语 CTC），却先跑了一遍 FireRedASR2 中文识别。** 主力转写用云端 API 时，兔白会在等云端结果的同时先用 FireRed 做中文字词时间，日语任务也不例外：FireRed 白跑几分钟（日语音频会输出一串重复字），然后结果被丢掉，再改用日语对齐。现在手动选日语或英语时不再启动 FireRed；选中文或「自动」时仍和云端转写同时进行，速度不变（「自动」识别出日语 / 英语时照旧丢掉这份结果）。进度里的 FireRedVAD 只检测哪里有人声，日语也要用，这一步照常显示。
- **MKV 成片的视频比声音短，仍显示导出成功。** MKV 常常不写视频自己的时长，以前的检查拿到的是更长的声音时长；现在按视频画面的实际时长核对，不一致就明确报错，不会留下画面提前结束的文件。MP4 以前就会拦下。

### What this release fixes (compared with 0.8.0)

A patch for 0.8.0 that fixes three problems reported by users, plus a gap in the MKV export check found while investigating them; no new features. Project, settings and recognition-result formats are unchanged. For everything in 0.8.0, see the [0.8.0 release notes](https://github.com/NOTBAD314/2ByteASR/releases/tag/v0.8.0).

- **In the Studio preview, picture and subtitles could run fast while the sound stayed at normal speed** (catching up only near the end). 2ByteASR plays the Studio sound itself, while the player paced video frames by the monitor's refresh rate; when Windows misreported that rate (for example as half the real one), the picture sped up, the subtitles followed the picture and the sound did not. Video now follows the system clock instead of the refresh rate and stays in sync with the sound at 1×, at 2× and after seeking.
- **After translating a two-person dialogue, the burned-in video lost one speaker's translation.** When one speaker used an advanced style (such as a gradient) or clips were trimmed on the timeline, that speaker's translation was missing from the video and from the preview shown while exporting. Normal and advanced styles, static and animated exports, and trimmed clips now all keep both translations.
- **SRT / TXT exported from the Home completion page now follow the Original / Translation / Bilingual display mode**; before, they always contained only the original. Per-speaker exports keep the translations too. The original / translation / bilingual choices in the Studio's Export subtitles (Ctrl+E) are unchanged.
- **With Japanese selected (subtitle timing by Qwen3 alignment / Japanese CTC), FireRedASR2 Chinese recognition ran first anyway.** When the main transcript comes from a cloud API, 2ByteASR uses the waiting time to compute Chinese word timing with FireRed — and it did so for Japanese tasks too: FireRed ran for minutes (producing a run of repeated characters on Japanese audio), its result was thrown away and Japanese alignment ran afterwards. FireRed no longer starts when you choose Japanese or English manually; with Chinese or Auto it still runs alongside the cloud transcript, so speed is unchanged (Auto still discards that result if the audio turns out to be Japanese or English). FireRedVAD in the progress list only detects where people speak; Japanese needs it too, so that step is still shown.
- **An MKV export whose video was shorter than its sound still reported success.** MKV files often do not store the video's own duration, so the old check saw the longer sound duration. The check now measures the video's actual duration and fails with a clear message instead of leaving a file whose picture ends early. MP4 exports were already caught.

### Updating from an earlier version

- **0.8.0**: "Check for updates" in the top-right corner of the main window downloads only the program part (about 52 MB).
- **0.7.x**: "Check for updates" downloads the program and license parts (about 80 MB). **0.6.5** additionally downloads the Python runtime and the renderer.
- The download is verified and replaces the program only after you save your project and agree to quit; if anything fails, the previous version is restored. Settings, term libraries, projects, downloaded models and runtimes are kept, and runtimes stay where they are.
- **0.6.0 or earlier**: quit 2ByteASR and run the 0.8.1 Setup **over the existing installation — do not uninstall first**.
- **Mac**: no in-app update yet. Quit the old version, open the new DMG and drag the app into Applications to replace it; settings, models and projects live in your user folder outside the app.

### Known limitations

### このバージョンで直したこと（0.8.0 との比較）

0.8.0 の修正版で、ユーザーから報告された 3 つの問題と、調査中に見つかった MKV 書き出し確認の抜けを直しました。新機能はありません。プロジェクト、設定、認識結果の形式は変わっていません。0.8.0 の全変更は [0.8.0 リリースノート](https://github.com/NOTBAD314/2ByteASR/releases/tag/v0.8.0)をご覧ください。

- **ワークベンチのプレビューで、音声は通常速度なのに映像と字幕が倍速のように進む**（最後のほうでようやく揃う）。ワークベンチの音声は 2ByteASR 自身が出力し、映像はプレーヤーがモニターのリフレッシュレートに合わせてフレームを並べていました。Windows がリフレッシュレートを誤って報告すると（例えば実際の半分）、映像が速くなり、字幕も映像に付いて進み、音声だけがそのままでした。映像はリフレッシュレートではなくシステム時計に従うようになり、1×・2×・シーク後も音声と同期します。
- **2 人の会話を翻訳して字幕を焼き込むと、1 人分の訳文が消える。** 片方がグラデーションなどの高度なスタイルを使っている場合や、タイムライン上でクリップをトリミングした場合、その人の訳文が動画にも書き出し中のプレビューにも入っていませんでした。通常・高度なスタイル、静的・アニメーションの書き出し、トリミングしたクリップのすべてで 2 人分の訳文が残ります。
- **ホームの完了ページから書き出す SRT / TXT が「原文／訳文／二言語」の表示モードに従うようになりました。** 以前は常に原文だけでした。話者ごとの書き出しも訳文を保ちます。ワークベンチの「字幕を書き出す（Ctrl+E）」の原文／訳文／二言語の選択は変わりません。
- **日本語（字幕タイミングは Qwen3 アライメント／日本語 CTC）を選んだのに、FireRedASR2 の中国語認識が先に実行される。** メインの文字起こしにクラウド API を使うとき、2ByteASR は結果を待つ間に FireRed で中国語の単語タイミングを先に計算しており、日本語のタスクでも同じでした。FireRed が数分間空回りし（日本語音声では同じ文字の繰り返しを出力）、結果は捨てられてから日本語のアライメントが実行されていました。日本語または英語を手動で選んだときは FireRed を起動しなくなりました。中国語と「自動」では従来どおりクラウドの文字起こしと並行するので、速度は変わりません（「自動」で日本語／英語と判定された場合はその結果を従来どおり捨てます）。進捗に出る FireRedVAD は音声のある区間を検出するだけで、日本語でも必要なため、この手順は引き続き表示されます。
- **映像が音声より短い MKV の書き出しが成功と表示される。** MKV は映像自体の長さを記録しないことが多く、以前の確認ではより長い音声の長さを見ていました。映像の実際の長さで確認し、一致しなければはっきりエラーにして、映像が途中で終わるファイルを残しません。MP4 は以前から検出されていました。

### 이번 버전에서 고친 것(0.8.0과 비교)

0.8.0의 패치로, 사용자가 알려 준 문제 세 가지와 조사 중에 찾은 MKV 내보내기 확인의 빈틈을 고쳤습니다. 새 기능은 없습니다. 프로젝트, 설정, 인식 결과 형식은 바뀌지 않았습니다. 0.8.0의 전체 변경은 [0.8.0 출시 노트](https://github.com/NOTBAD314/2ByteASR/releases/tag/v0.8.0)를 보세요.

- **워크벤치 미리보기에서 소리는 정상 속도인데 화면과 자막이 배속처럼 빨라짐**(끝 무렵에야 다시 맞음). 워크벤치 소리는 2ByteASR가 직접 내보내고, 화면은 플레이어가 모니터 주사율에 맞춰 프레임을 배치했습니다. Windows가 주사율을 잘못 보고하면(예: 실제의 절반) 화면이 빨라지고 자막도 화면을 따라가며 소리만 그대로였습니다. 이제 화면이 주사율이 아니라 시스템 시계를 따라 1×, 2×, 탐색 후에도 소리와 맞습니다.
- **두 사람의 대화를 번역해 자막을 입힌 영상에서 한 사람의 번역이 빠짐.** 한 사람이 그라데이션 같은 고급 스타일을 쓰거나 타임라인에서 클립을 잘랐을 때, 그 사람의 번역이 영상에도, 내보내는 동안의 미리보기에도 없었습니다. 이제 일반·고급 스타일, 정적·모션 내보내기, 자른 클립 모두 두 사람의 번역을 유지합니다.
- **홈 완료 페이지에서 내보내는 SRT / TXT가 "원문 / 번역 / 이중 언어" 표시 모드를 따릅니다.** 전에는 항상 원문만 들어 있었습니다. 화자별 내보내기도 번역을 유지합니다. 워크벤치 "자막 내보내기(Ctrl+E)"의 원문 / 번역 / 이중 언어 선택은 그대로입니다.
- **일본어(자막 타이밍은 Qwen3 정렬 / 일본어 CTC)를 골랐는데 FireRedASR2 중국어 인식이 먼저 실행됨.** 주 받아쓰기에 클라우드 API를 쓸 때 2ByteASR는 결과를 기다리는 동안 FireRed로 중국어 단어 타이밍을 미리 계산했는데, 일본어 작업에서도 그랬습니다. FireRed가 몇 분 동안 헛돌고(일본어 음성에서는 같은 글자를 반복 출력) 그 결과를 버린 뒤에야 일본어 정렬을 했습니다. 이제 일본어나 영어를 직접 고르면 FireRed를 시작하지 않습니다. 중국어와 "자동"은 그대로 클라우드 받아쓰기와 동시에 실행하므로 속도는 같습니다("자동"에서 일본어·영어로 판정되면 그 결과는 예전처럼 버립니다). 진행 상황의 FireRedVAD는 말소리 구간만 찾으며 일본어에도 필요해서 계속 표시됩니다.
- **영상이 소리보다 짧은 MKV 내보내기가 성공으로 표시됨.** MKV는 영상 자체의 길이를 적지 않는 경우가 많아 예전 확인은 더 긴 소리 길이를 봤습니다. 이제 영상의 실제 길이로 확인해 맞지 않으면 분명한 오류로 끝나고, 화면이 일찍 끝나는 파일을 남기지 않습니다. MP4는 예전부터 걸러졌습니다.

- **Claude**: Anthropic 공식 지원 지역에 중국 본토, 홍콩, 마카오는 없습니다.
- 0.8.0 출시 노트의 나머지 알려진 제한(실행 환경 위치, 이전 버전에서 새 프로젝트 열기, 온라인 용어집, 수식, 로컬 MCP, 화면 번역, 4× 재생에서 가끔 멈추는 문제, 제3자 라이선스)은 그대로입니다.
