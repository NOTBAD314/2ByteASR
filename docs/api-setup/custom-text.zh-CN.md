# 自定义 OpenAI 兼容服务（文字 AI，进阶）

最后核对：2026-10-14。来源见文末。标“待核实”的地方需要登录才能确认。

一般使用者不需要这一项。它适合两种情况：你自己在电脑或服务器上架设了模型服务；或某家服务商提供“OpenAI 兼容”的聊天接口，而兔白的“AI 服务”下拉里没有它。

## 先看结论

| 问题 | 回答 |
| --- | --- |
| 在兔白里做什么 | 文字 AI：AI 断句、字幕校对、翻译。**只发送字幕文字，不上传音频** |
| 在哪里填 | 「AI 智能断句设置」→“AI 服务”选 **自定义 OpenAI-Compatible** |
| 对服务的要求 | 支持 OpenAI 格式的 `/chat/completions`（或 `/responses`）接口，用 `Authorization: Bearer` 方式传密钥 |
| 最容易填错的 | **Base URL 只填到“根地址”**，通常以 `/v1` 结尾；不要填完整请求地址，兔白会自己补后面的路径 |
| 要花钱吗 | 由你用的服务决定。兔白不知道、也不显示第三方服务的价格 |
| 兔白验证状态 | 兼容接口已有接入；你填的具体服务兔白没有测过，请以“测试连接”结果为准 |

## 它在兔白里做什么

- **AI 断句**：把识别出的整段文字切成适合看的字幕句子（“全文断句使用 AI”）。
- **字幕校对**：修正错别字、专有名词、标点（“字幕校对使用 AI”）。
- **翻译**：日语任务识别后翻成中文，以及字幕工作室里的“翻译 / 生成双语字幕”。翻译用的是“字幕校对模型”那一套设置。
- 同一套设置也用于术语整理、字幕工作室的“AI 设计”等辅助功能。
- 兔白要求模型按固定 JSON 格式回答。模型太小或不擅长按格式回答时，测试可能通过、正式任务却频繁失败（完成页会写“原文回退 N 批”）。

## 官方链接

这一项没有固定的官方网站，请看你所用服务的说明文档，找它写的 **Base URL**（有的叫 “API Base”“base_url”“接入点”）、模型名和 API Key 的申请页面。

## 从零开始

1. 在你的服务商那里拿到三样东西：Base URL、模型名、API Key（本机自架服务可能不需要 Key）。
2. 打开兔白的「AI 智能断句设置」，任选一种方式：
   - 首页“AI 智能断句”卡片上的“设置 AI”按钮（或直接点这张卡片）
   - 模型工坊 →“AI 模型 / 智能断句”
   - 「申请与设置 API」里这篇教程下方的“去填写这家服务的密钥”（打开后仍要在“AI 服务”里自己选“自定义 OpenAI-Compatible”）
3. 在“AI 服务”下拉里选 **自定义 OpenAI-Compatible**。这时会多出“Provider 名称”一栏，进阶区也会自动展开。
4. 填“Base URL”“模型”“API 密钥”（下表），点“测试连接”。
5. 看到“连接测试通过”后，点对话框右下角“保存设置”。

**一张卡片还是两张**：对话框上方的开关“同一云端模型负责字幕校对与全文断句（推荐）”默认打开，这时只有一张卡片，标题是“统一校对与断句模型”。关掉后会出现“字幕校对模型”和“全文断句模型”两张卡片，各自选服务、各自填密钥。

## 需不需要开通服务、充值或储存空间

由你的服务商决定。兔白这边不需要额外开通，也不需要 OSS 等储存空间。

## 兔白里的每一栏

| 栏位 | 做什么用 | 例子 | 从哪里来 | 已预填？ |
| --- | --- | --- | --- | --- |
| AI 服务 | 选用哪家服务 | `自定义 OpenAI-Compatible` | 下拉选择 | 需要自己选 |
| Provider 名称 | 给这个服务起个名字，只用于显示 | `我的本机模型` | 自己起 | 是（`自定义服务`），可改可不改 |
| API 密钥 | 服务要求的密钥 | 服务商给的一串字符 | 服务商的 Key 页面 | 否。只有本机服务（地址是 `localhost`、`127.0.0.1` 或 `[::1]`）可以留空 |
| 模型 | 服务要求的模型名 | 服务商文档里写的模型 ID | 服务商文档，或点“刷新模型” | **否**。下拉里可能残留别家服务的模型名，那些不一定适用，请填你的服务要求的名字 |
| Base URL（进阶区，已自动展开） | 服务的根地址 | `https://example.com/v1` | 服务商文档 | **否**，必须填 |
| 协议 / Protocol（进阶） | 请求格式 | `Auto`；服务只支持 Responses 接口时选 `Responses API` | 服务商文档 | 是（`Auto`）。不确定就用 Auto |
| JSON Mode、Structured Output（进阶） | 要求模型按固定格式回答 | 勾选 | — | 已勾选。一般不用改 |
| stream（进阶） | 灰色不可选；兔白目前不用流式 | — | — | — |

### 地址怎么填（不用猜 `/v1`）

| 名称 | 例子 | 说明 |
| --- | --- | --- |
| 官方网站 | `https://example.com/` | 服务商首页，兔白不用 |
| API Host | `example.com` | 只是主机名，兔白不用单独填 |
| **Base URL（填进兔白）** | `https://example.com/v1` | 照抄服务商文档写的 Base URL。文档写带 `/v1` 就带，不带就不带 |
| 完整请求 Endpoint | `https://example.com/v1/chat/completions` | 兔白自动拼出来，进阶区“实际请求：”一行会显示 |

- 协议为 `Auto`、`Chat Completions` 或 `OpenAI-compatible Chat` 时，兔白在 Base URL 后面加 `/chat/completions`；选 `Responses API` 时加 `/responses`。
- 如果你误把完整地址（以 `/chat/completions` 结尾）贴进 Base URL，兔白会自动去掉这段；`/v1/v1` 也会自动合并成一个，不会重复。
- 必须是 `https://` 地址；只有本机服务可以用 `http://`。地址里不能带用户名密码、`?` 后面的参数或 `#` 片段。

## 测试时会看到什么

**测试连接**：兔白用这张卡片上的地址、模型和密钥（刚贴进去还没保存的密钥也会用）发一句很短的固定文字，要求模型只回一小段 JSON，最多等 45 秒。是否收费由你的服务决定。

- 成功时状态行显示：`连接测试通过 · 中文 JSON 字段正确 · 兼容 JSON／本地校验 · 1.23s`（选 Responses API 时中间是“原生 JSON Schema＋本地校验”）。如果卡片上选的服务和上次保存的不同，后面还会加“尚未保存：点击保存后 AI 设计才会使用此 Provider”。
- 首页 AI 卡片下方会显示“连接正常”；失败显示“连接失败”；还没测过显示“尚未测试连接”。
- 失败时状态行显示服务的错误，例如 `HTTP 404：……`，对照下表处理。

**刷新模型**：向服务读取模型列表（不让模型生成文字）。很多兼容服务不提供这个列表，读不到时会提示“可手动输入模型 ID”，直接在“模型”里输入即可。

## 常见失败与下一步

| 现象 | 可能原因 | 下一步 |
| --- | --- | --- |
| “当前模型（custom）缺少模型名称……” | “模型”是空的 | 填上服务商文档里的模型名 |
| “当前模型（custom）缺少 API 密钥……” | 远程服务必须填密钥 | 贴入服务商给的 Key；本机服务请把地址写成 `localhost` 或 `127.0.0.1` |
| “当前模型的 API 地址无效。请填写 OpenAI 兼容的 HTTPS 地址。” | Base URL 没写 `https://`，或格式不对 | 照服务商文档重新复制 Base URL |
| “……只允许 HTTPS；HTTP 仅可用于本机回环地址。” | 远程服务用了 `http://` | 改用服务商的 `https://` 地址 |
| `HTTP 404` | Base URL 少了或多了一段路径（最常见是 `/v1`） | 对照服务商文档：文档的 Base URL 带 `/v1` 你就带上；看进阶区“实际请求：”是否和文档的完整地址一致 |
| `HTTP 401` / `HTTP 403` | 密钥错误，或服务不是用 Bearer 方式认证 | 重新复制 Key；如果服务要求别的认证方式，这一项无法使用 |
| `HTTP 400`，提到模型 | 模型名不对 | 改成服务商文档里的模型 ID，或点“刷新模型”选 |
| `HTTP 400`，提到 `response_format` | 服务不支持 JSON 格式参数 | 兔白会自动去掉这个参数重试一次；仍失败说明这个服务不适合兔白，改用“AI 服务”下拉里的现成服务 |
| 测试通过，但任务完成页常写“原文回退 N 批” | 模型回答的格式不稳定，或请求太长 | 换一个更强的模型；或改用“AI 服务”下拉里的现成服务 |
| 连不上（超时、无法连接） | 地址打不开、服务没启动 | 确认服务在运行、网络能打开这个地址 |

## 隐私与费用

- **传到哪里**：你在 Base URL 里填的地址。请确认你信任这个服务。
- **传什么**：字幕文字，以及你填写的游戏 / 内容名称和术语提示。**不发送音频**。字幕工作室的“AI 设计”在模型支持看图时，可能附带画面截图或字幕效果预览图。
- **密钥**：只保存在本机。Windows 用 DPAPI 加密；macOS 存在“钥匙串”，钥匙串不可用时只保留到退出软件，绝不存明文。不写进工程、日志或导出文件。
- **费用**：由你的服务商决定，兔白无法替你确认。

## 进阶（一般使用者可跳过）

- 请求：`POST {Base URL}/chat/completions`（或 `/responses`），头部 `Authorization: Bearer <密钥>`；需要按 JSON 回答时附 `response_format: {"type": "json_object"}`。服务端回 400 且错误里提到 `response_format`、`json_object`、`structured output` 或 `unsupported` 时，兔白自动去掉该参数重试一次。测试连接的内容是一句要求回 `{"ok":true,"text":"兔白字幕"}` 的提示，最多 80 个输出 token。
- “刷新模型”：Base URL 带路径（例如 `https://example.com/v1`）时请求 `{Base URL}/models`；Base URL 只有主机名（例如 `https://example.com`）时请求 `https://example.com/v1/models`。后一种情况聊天请求却是 `https://example.com/chat/completions`，两者可能对不上——这也是建议照抄文档 Base URL（通常带 `/v1`）的原因。
- 密钥按“服务 + 域名”分开保存，换到别的域名需要重新填。
