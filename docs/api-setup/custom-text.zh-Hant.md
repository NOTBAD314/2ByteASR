# 自定義 OpenAI 相容服務（文字 AI，進階）

最後核對：2026-10-14。來源見文末。標“待核實”的地方需要登入才能確認。

一般使用者不需要這一項。它適合兩種情況：你自己在電腦或伺服器上架設了模型服務；或某家服務商提供“OpenAI 相容”的聊天介面，而兔白的“AI 服務”下拉里沒有它。

## 先看結論

| 問題 | 回答 |
| --- | --- |
| 在兔白裡做什麼 | 文字 AI：AI 斷句、字幕校對、翻譯。**只發送字幕文字，不上傳音訊** |
| 在哪裡填 | 「AI 智慧斷句設定」→“AI 服務”選 **自定義 OpenAI-Compatible** |
| 對服務的要求 | 支援 OpenAI 格式的 `/chat/completions`（或 `/responses`）介面，用 `Authorization: Bearer` 方式傳金鑰 |
| 最容易填錯的 | **Base URL 只填到“根地址”**，通常以 `/v1` 結尾；不要填完整請求地址，兔白會自己補後面的路徑 |
| 要花錢嗎 | 由你用的服務決定。兔白不知道、也不顯示第三方服務的價格 |
| 兔白驗證狀態 | 相容介面已有接入；你填的具體服務兔白沒有測過，請以“測試連線”結果為準 |

## 它在兔白裡做什麼

- **AI 斷句**：把識別出的整段文字切成適合看的字幕句子（“全文斷句使用 AI”）。
- **字幕校對**：修正錯別字、專有名詞、標點（“字幕校對使用 AI”）。
- **翻譯**：日語任務識別後翻成中文，以及字幕工作室裡的“翻譯 / 生成雙語字幕”。翻譯用的是“字幕校對模型”那一套設定。
- 同一套設定也用於術語整理、字幕工作室的“AI 設計”等輔助功能。
- 兔白要求模型按固定 JSON 格式回答。模型太小或不擅長按格式回答時，測試可能通過、正式任務卻頻繁失敗（完成頁會寫“原文回退 N 批”）。

## 官方連結

這一項沒有固定的官方網站，請看你所用服務的說明文件，找它寫的 **Base URL**（有的叫 “API Base”“base_url”“接入點”）、模型名和 API Key 的申請頁面。

## 從零開始

1. 在你的服務商那裡拿到三樣東西：Base URL、模型名、API Key（本機自架服務可能不需要 Key）。
2. 開啟兔白的「AI 智慧斷句設定」，任選一種方式：
   - 首頁“AI 智慧斷句”卡片上的“設定 AI”按鈕（或直接點這張卡片）
   - 模型工坊 →“AI 模型 / 智慧斷句”
   - 「申請與設定 API」裡這篇教程下方的“去填寫這家服務的金鑰”（開啟後仍要在“AI 服務”裡自己選“自定義 OpenAI-Compatible”）
3. 在“AI 服務”下拉里選 **自定義 OpenAI-Compatible**。這時會多出“Provider 名稱”一欄，進階區也會自動展開。
4. 填“Base URL”“模型”“API 金鑰”（下表），點“測試連線”。
5. 看到“連線測試通過”後，點對話方塊右下角“儲存設定”。

**一張卡片還是兩張**：對話方塊上方的開關“同一雲端模型負責字幕校對與全文斷句（推薦）”預設開啟，這時只有一張卡片，標題是“統一校對與斷句模型”。關掉後會出現“字幕校對模型”和“全文斷句模型”兩張卡片，各自選服務、各自填金鑰。

## 需不需要開通服務、充值或儲存空間

由你的服務商決定。兔白這邊不需要額外開通，也不需要 OSS 等儲存空間。

### 地址怎麼填（不用猜 `/v1`）

| 名稱 | 例子 | 說明 |
| --- | --- | --- |
| 官方網站 | `https://example.com/` | 服務商首頁，兔白不用 |
| API Host | `example.com` | 只是主機名，兔白不用單獨填 |
| **Base URL（填進兔白）** | `https://example.com/v1` | 照抄服務商文件寫的 Base URL。文件寫帶 `/v1` 就帶，不帶就不帶 |
| 完整請求 Endpoint | `https://example.com/v1/chat/completions` | 兔白自動拼出來，進階區“實際請求：”一行會顯示 |

- 協議為 `Auto`、`Chat Completions` 或 `OpenAI-compatible Chat` 時，兔白在 Base URL 後面加 `/chat/completions`；選 `Responses API` 時加 `/responses`。
- 如果你誤把完整地址（以 `/chat/completions` 結尾）貼進 Base URL，兔白會自動去掉這段；`/v1/v1` 也會自動合併成一個，不會重複。
- 必須是 `https://` 地址；只有本機服務可以用 `http://`。地址裡不能帶使用者名稱密碼、`?` 後面的引數或 `#` 片段。

## 測試時會看到什麼

**測試連線**：兔白用這張卡片上的地址、模型和金鑰（剛貼進去還沒儲存的金鑰也會用）發一句很短的固定文字，要求模型只回一小段 JSON，最多等 45 秒。是否收費由你的服務決定。

- 成功時狀態行顯示：`連線測試通過 · 中文 JSON 欄位正確 · 相容 JSON／本地校驗 · 1.23s`（選 Responses API 時中間是“原生 JSON Schema＋本地校驗”）。如果卡片上選的服務和上次儲存的不同，後面還會加“尚未儲存：點選儲存後 AI 設計才會使用此 Provider”。
- 首頁 AI 卡片下方會顯示“連線正常”；失敗顯示“連線失敗”；還沒測過顯示“尚未測試連線”。
- 失敗時狀態行顯示服務的錯誤，例如 `HTTP 404：……`，對照下表處理。

**重新整理模型**：向服務讀取模型列表（不讓模型生成文字）。很多相容服務不提供這個列表，讀不到時會提示“可手動輸入模型 ID”，直接在“模型”裡輸入即可。

## 常見失敗與下一步

| 現象 | 可能原因 | 下一步 |
| --- | --- | --- |
| “當前模型（custom）缺少模型名稱……” | “模型”是空的 | 填上服務商文件裡的模型名 |
| “當前模型（custom）缺少 API 金鑰……” | 遠端服務必須填金鑰 | 貼入服務商給的 Key；本機服務請把地址寫成 `localhost` 或 `127.0.0.1` |
| “當前模型的 API 地址無效。請填寫 OpenAI 相容的 HTTPS 地址。” | Base URL 沒寫 `https://`，或格式不對 | 照服務商文件重新複製 Base URL |
| “……只允許 HTTPS；HTTP 僅可用於本機迴環地址。” | 遠端服務用了 `http://` | 改用服務商的 `https://` 地址 |
| `HTTP 404` | Base URL 少了或多了一段路徑（最常見是 `/v1`） | 對照服務商文件：文件的 Base URL 帶 `/v1` 你就帶上；看進階區“實際請求：”是否和文件的完整地址一致 |
| `HTTP 401` / `HTTP 403` | 金鑰錯誤，或服務不是用 Bearer 方式認證 | 重新複製 Key；如果服務要求別的認證方式，這一項無法使用 |
| `HTTP 400`，提到模型 | 模型名不對 | 改成服務商文件裡的模型 ID，或點“重新整理模型”選 |
| `HTTP 400`，提到 `response_format` | 服務不支援 JSON 格式引數 | 兔白會自動去掉這個引數重試一次；仍失敗說明這個服務不適合兔白，改用“AI 服務”下拉里的現成服務 |
| 測試通過，但任務完成頁常寫“原文回退 N 批” | 模型回答的格式不穩定，或請求太長 | 換一個更強的模型；或改用“AI 服務”下拉里的現成服務 |
| 連不上（超時、無法連線） | 地址打不開、服務沒啟動 | 確認服務在執行、網路能開啟這個地址 |

## 隱私與費用

- **傳到哪裡**：你在 Base URL 裡填的地址。請確認你信任這個服務。
- **傳什麼**：字幕文字，以及你填寫的遊戲 / 內容名稱和術語提示。**不傳送音訊**。字幕工作室的“AI 設計”在模型支援看圖時，可能附帶畫面截圖或字幕效果預覽圖。
- **金鑰**：只儲存在本機。Windows 用 DPAPI 加密；macOS 存在“鑰匙串”，鑰匙串不可用時只保留到退出軟體，絕不存明文。不寫進工程、日誌或匯出檔案。
- **費用**：由你的服務商決定，兔白無法替你確認。

## 進階（一般使用者可跳過）

- 請求：`POST {Base URL}/chat/completions`（或 `/responses`），頭部 `Authorization: Bearer <金鑰>`；需要按 JSON 回答時附 `response_format: {"type": "json_object"}`。服務端回 400 且錯誤裡提到 `response_format`、`json_object`、`structured output` 或 `unsupported` 時，兔白自動去掉該引數重試一次。測試連線的內容是一句要求回 `{"ok":true,"text":"兔白字幕"}` 的提示，最多 80 個輸出 token。
- “重新整理模型”：Base URL 帶路徑（例如 `https://example.com/v1`）時請求 `{Base URL}/models`；Base URL 只有主機名（例如 `https://example.com`）時請求 `https://example.com/v1/models`。後一種情況聊天請求卻是 `https://example.com/chat/completions`，兩者可能對不上——這也是建議照抄文件 Base URL（通常帶 `/v1`）的原因。
- 金鑰按“服務 + 域名”分開儲存，換到別的域名需要重新填。
